## 1. 为什么百叶违和，新的要守住什么

百叶是深色金属木条加一团光，后面整站是纸和墨线，两种材质不是一个世界。所以新 hero 的规矩只有一条：**从第一个像素起就是纸和墨**，不再有深色、金色、渐变光。

要去掉的：`src/components/Hero.jsx` 里的百叶、光晕、「The light behind these louvres…」那句话、窗台、穿窗（`push`）。

要留下的：标题「A Sanctuary Above All」、`Unofficial concept · George Town, Penang`、副标那两句、George Town 的时间和坐标、真实太阳（这次它照的是立起来的房子，有东西可照）。

## 2. 新的 hero

一句话：**一张白纸，园区的平面图一笔一笔画出来；往下滚，镜头斜下来，房子从平面图上长高，George Town 此刻的太阳把影子落在地上，然后镜头直接降到大门。**

这正是这个世界真实的来历：它就是从那张总平面图搭起来的（`src/data/sitePlan.js` → `src/ink/site.js`）。

### 2.2 细节

- **「画出来」用 SVG 做，不用等三维。** `sitePlan.js` 的线一进站就有，用 `stroke-dashoffset` 一条条画。三维世界（`estate` 分块）同时在后面搭；搭好之前用户看到的是正在画的平面图，不是空白，也不是加载圈。上一版最大的风险「进站要等园区搭好」由此解决。
- **SVG 换成三维的那一下**：三维这时是正上方看、房子高度接近 0，画出来就是同一张平面。SVG 和画布对齐后（见 §3.2）交叉淡化，约 0.2 屏的滚动里换完。两边的线不完全一样（SVG 里有设施图例的轮廓，三维里是体块的边），淡化能盖过去；**对不对得上要看样片**。
- **长高**：先做最简单的——整个 `estate` 分块沿竖直方向从 0 缩放到 1（缓动）。看了样片如果觉得呆，再改成一排一排先后长（把 `estate` 拆成几个分块，各自缩放）。
- **影子**：长高期间每一帧都要重算影子图（`renderer.shadowMap.needsUpdate = true`）；长完就停（现有规矩：光不动就不重算）。
- **太阳**：和一镜到底同一套（`sunWorld`）；天黑时用「当天第一道 / 最后一道光」，图注相应改写（现成逻辑）。
- **标题和文案**：标题只在平面图阶段出现。底部提示的字是新起的（例如「Scroll ↓」或「Scroll to walk in ↓」），**要用户过目**；其余都是站内已有的话。原来的按钮「Walk the Estate →」拿掉。
- **菜单**：首屏就是纸色，菜单从一开始就是纸色墨字（`Navbar.jsx` 现有的判断已经能做到：菜单压在 `.take` 上就变纸色）。
- **开场幕布**（`Preloader`，深色）：一镜到底这一版不要了，平面图自己画出来就是开场。分段页面照旧用。
- **手机**：平面图是竖长的（516×789），竖屏正好；标题和小字放在平面图上方和下方，不压在图上。横屏（桌面）平面图居右，标题在左。

### 2.3 页面顺序

平面图立起来之后就是一镜到底，所以一镜到底必须紧跟首屏。新顺序：

1. Hero + 一镜到底（合成一段，纸色）
2. Location（深色，原样）
3. Masterplan（深色，原样——首屏的平面图是「画」，这一段是可以点的图例，不重复）
4. Enquire 表单（深色）
5. Footer

跟着要改的：

- 一镜到底现在的开头（`id: 'plan'` 的俯视位）本来就是「正上方看平面图再翻下来」，正好成为 hero；只是原来它前面有 Masterplan 段，现在没有了。之前记着的缺口「Masterplan → 一镜到底没有对齐」自然消失。
- 菜单顺序改成：Facilities ▾ · Residences ▾ · Location · Masterplan · Register；`#about` 指向 hero。
- 一镜到底结尾（纸色）接 Location（深色）：不做花样，纸到头就是深色，像一张纸放在深色桌面上，边上留一道细影。
- 表单的位置见 §6.1。

## 3. 做法（给 Opus）

涉及：新的 `src/ink/PlanDraw.jsx`（SVG 平面图，会自己画出来）、`src/ink/Take.jsx`、`src/ink/take-route.js`、`src/ink/stage.js`（分块缩放）、`src/components/Hero.jsx`（改成后备用的薄壳）、`src/components/Navbar.jsx`、`src/App.jsx`、`src/sample.jsx`。

### 3.1 `PlanDraw`

- 输入：调色（纸墨 / 深金）、`drawn`（0–1，画到哪了，或者「自己放一遍」）。
- 数据直接用 `src/data/sitePlan.js`（`lines`、`paths`、`rects`、`circles`，带分组 id）。`Take.jsx` 的小地图已经在用同一份数据画 SVG（`viewBox="20 20 480 750"`），照它的写法。
- 画的顺序按分组排：外轮廓 → 车道 → 地块（按排）→ 泳池谷和设施。每条线用 `pathLength="1"` + `stroke-dashoffset`，交错开始。总时长约 2.5 秒；减少动态时直接画完。
- 线宽用 `vector-effect: non-scaling-stroke`，缩放时不变粗。

### 3.2 SVG 和三维对齐

- hero 的俯视关键位：眼睛在目标正上方约 330 m（现有 `plan` 位是 `eye: [-12, 330, 26], at: [-12, 0, 6]`，有 3.5° 的倾斜；hero 要正的，把眼睛的 z 改成只比目标偏 0.5 m，保证「上 = 北」又不让 `lookAt` 退化）。`stage.js` 的 `FAR = 400`，330 m 够。
- 这时所有东西都在一个平面上，三维画面和平面图之间只差一个缩放加平移。每次 `resize` 和每帧（只在 hero 阶段）用 `stage.project()` 投两个已知的点（例如平面图的两个对角，世界坐标用 `site.js` 的 `W()` 换），算出 SVG 的 `transform`。
- 手机竖屏用关键位的 `keep`（现有 0.62）保证平面图不被裁。
- 镜头开始倾斜之前 SVG 必须已经淡完（倾斜后就不是缩放加平移了）。

### 3.3 长高

- `stage.js`：`chunk()` 现在返回前把分块的 `THREE.Group` 存在 `chunks` 里。加一个 `scaleY(name, k)`：设 `g.scale.y = k`、`g.updateMatrixWorld(true)`、`renderer.shadowMap.needsUpdate = true`。线是屏幕空间宽度（`LineSegments2`），缩放不影响粗细。
- 所有高度以谷底 y = 0 为基准，所以缩到 0 就是全部压到谷底平面，正好是平面图。
- `k` 很小时所有面几乎重合，点画（tone pass）会闪。画布在 `k < 0.03` 时不显示（这段由 SVG 顶着）；0.03 时最矮的也有几十厘米，330 m 外的深度精度（约 7 mm）够分开。
- `Take.jsx` 的 `draw(s)` 按 `s` 算 `k`（0 → 0.3 在俯视阶段，0.3 → 1 在倾斜阶段），和标注同一个时钟，不另挂 scroll 监听。
- 近处的分块（`PIECES`）在镜头高于 120 m 时本来就不搭，hero 阶段只有 `estate` 一个分块，显存约 40 MB（手机整页峰值 115 MB 在路线中段，不受影响，但样片要量）。
- **鸟瞰只有体块**：全高之后的那张斜鸟瞰是全站第二眼，只有体块可能偏素。先看样片；不够的话加一个只在高处存在的「远景」分块（谷里的水面线、沿谷的树、屋顶的几道线，只用线不加面），降到大门前释放。

### 3.4 路线

`take-route.js` 的 `KEYS` 开头改成：正俯视（hero）→ 同一个位置再停一拍（房子长到三成）→ 现有的斜鸟瞰位（`eye: [-40, 170, 300]`，按样片调低一些让园区更满）→ 现有 `eye: [-18, 30, 215]` → 大门。`ANCHORS.about = 'plan'` 不变。

### 3.5 页面

```
一镜到底版： <Take />（含 hero）→ <Location scrub /> → <Masterplan /> → <Enquire />      不放 <Preloader />
分段版：     <Preloader /> → <Hero />（PlanDraw 深金，静态）→ 其余原样
```

## 4. 做的顺序

每一步：`npx eslint src` 干净、`npx vite build` 通过、截图看过、提交、推分支（`claude/zoom-in-restructure`）。拍片时不要改被 Vite 服务的文件。拍片要接着拍或者分两次拍时，用 `TIME=` 把时钟拨到同一刻（否则影子在接缝处跳）。

1. **样片（先给用户看，说好再往下）**：`sample.html?hero`——`PlanDraw` 自己画出来 → 换成三维 → 影子爬出来 → 斜下来长到全高 → 降到大门前为止。不动正式页面，不需要 §6 的决定。交付：桌面和手机各一段逐帧拍的视频、四张截图（画到一半 / 画完 / 影子爬出来 / 全高鸟瞰）、手机显存数字。
2. 用户说好、定了 §6 之后：并进 `Take.jsx`，`App.jsx` 改顺序，菜单顺序，去掉这一版的 `Preloader`。
3. 表单按 §6.1 定的位置放；一镜到底结尾接 Location。
4. 后备：分段页面的 hero 换成深金的 `PlanDraw`；删掉百叶。
5. 整页验证：手机 / 桌面逐站截图；`gpu-budget.cjs 390 844`（≤ 120 MB）；`?sections`、减少动态；菜单每一项和下拉每一站都落在对的地方；页面上没有项目名、没有开发商的图；仍然标着 unofficial concept。
6. 整页拍片（桌面 + 手机），更新预览（https://claude.ai/artifact/Jre1pSm1Pru5rPTjEi9nTn）。
7. 清理和文档：`docs/animation-plan.md`、`docs/world-plan.md`、`.claude/skills/ink-drawing/SKILL.md`。

## 5. 不确定的地方

- **SVG 换成三维时对不对得上**：两边的线不是同一批（图例轮廓 vs 体块的边），要看样片。对不上的话，改成三维里也画一遍平面图的线（`site.js` 的 `LINES`），SVG 只负责进站头两秒。
- **整体缩放的长高好不好看**，要看样片；备选是一排一排先后长。
- **只有体块的斜鸟瞰够不够**，要看样片；备选是加远景分块（§3.3）。
- **长高时每帧重算影子**，手机上的帧率软件渲染里量不出来，要用户在手机上滚一遍。
- **高度都是估的**（来自一张很小的剖面草图）。房子「长到多高」正是这一屏的主角，页面上那句「Heights… are our reading」在 hero 阶段就要看得到。
- 页面总长：百叶的 2.5 屏和 Masterplan 前的衔接去掉，hero 约 1.2 屏并在一镜到底里，整页大约少 1–2 屏（现在约 43 屏）。整体缩短是另一件事。

## 1. 现在的 hero 哪里不对（看过截图和代码）

`src/components/Hero.jsx`（`push` 模式，250svh）：

1. **和后面是两个世界。** 首屏是深色 + 金色的百叶和一团光晕；整站的主角是纸色墨线的园区。首屏没有预告网站最特别的东西。
2. **百叶打开，后面没东西看。** 只有一团渐变光和一句解释光的话（「The light behind these louvres is George Town’s, right now…」）。那句话说的是真的（光是按真实太阳算的），但没有东西被这道光照着，所以读起来只是一句说明。
3. **穿过窗子以后是一片深色**（`hero-veil` 盖成 Location 的底色）。「穿窗」这个动作没有回报。
4. 标题、副标、按钮的排法是楼盘网站的通用排法。

要留下的：百叶本身（开合、鼠标掀动、开场那一道波）、真实太阳、底下那条窗台（文案和时间坐标）。这些是好的，问题只在「百叶后面」和「穿过去以后」。

## 2. 新的 hero（方向 A）

一句话：**百叶是加载时的盖子，也是第一个镜头的窗框；后面就是一镜到底的第一帧——整个园区的墨线鸟瞰，被 George Town 此刻的太阳照着。往下滚，窗框退出画面，镜头直接飞进园区。**

### 2.1 一屏一屏看

滚动量以「屏」计（1 屏 = 100svh）。

| 滚到 | 画面 |
|---|---|
| 进站 | 深色百叶关着，标题「A Sanctuary Above All」印在百叶上（现在的做法，保留）。园区在后面搭好第一帧之前百叶不开——它就是加载盖子。第一帧好了，百叶过一道波，缝里闪过纸色。 |
| 0 → 0.3 | 百叶从左到右依次转开（现有的 `OPEN_END = 0.3`）。露出来的不是光晕，是**纸色底、墨线画的整个园区**：两排 Homes、中间的泳池谷、三层车道、大门，影子是此刻太阳的方向。镜头在这段极慢地往前推（约 3%），画在百叶缝后面是活的。 |
| 0.3 → 0.9 | 百叶全开（转到侧面几乎看不见）。画的左下角用墨色小字写：`George Town · 9:17 am · the sun is 30° above the horizon, to the east-southeast`（现在那句话的内容，改成图注的样子）。窗台还在。 |
| 0.9 → 1.5 | 窗台往下滑出画面，百叶淡掉，画铺满全屏；菜单同时从深色换成纸色（上一轮已经做好的切换）。镜头开始下降。 |
| 1.5 以后 | 就是一镜到底：从鸟瞰降到街上、大门前（现有路线的第 3 个关键位起原样接上）。 |

### 2.2 细节

- **鸟瞰的角度**：从南偏西的高处斜着看全园（大约眼睛高 90–100 m，离园区中心 250 m 左右，具体由 Opus 对着截图调）。手册第 3 页有一张鸟瞰效果图，可以参照它的角度，但画是我们自己这个世界画出来的。
- **画面要压在窗子里构图**：窗台占屏幕下方约四分之一，开窗阶段画的中心要在窗子（上方约四分之三）的中间，用路线关键位现成的 `shift` 把画往上移；窗台滑走时 `shift` 回到 0。
- **第一帧不能是光秃秃的体块。** 现在镜头高于 120 m 时只画体块（`Take.jsx` 里 `eye[1] < 120`），细的部分都在 110 m 以内才搭。hero 这一帧是全站第一眼，要加一个只在这一段存在的「远景装扮」分块：谷里的水面线、沿谷的树、屋顶和立面的几道线（只用线，不加面），镜头降下去后释放。
- **太阳**：和一镜到底同一套（`sunWorld`），天黑时照旧用「当天第一道 / 最后一道光」，图注相应改写（现成的逻辑）。画里的太阳圆盘（`tk-disc`）保留。
- **标题**：只印在百叶上，开了就没有了；全开后画上只留那行图注。`<h1>` 照旧给读屏。
- **窗台文案**：`Unofficial concept · George Town, Penang`、「239 exclusive residences…」原样（都是站内已有的话）。按钮从「Walk the Estate →」改成一个往下的提示（例如「Scroll to walk in ↓」），因为往下滚本身就是走进去。**按钮上的字是新起的，要用户过目。**
- **鼠标**：桌面上鼠标掀动百叶保留。
- **手机**：百叶条数照旧按宽度算；鸟瞰用路线的 `keep` 保证竖屏里园区不被裁掉。

### 2.3 页面顺序跟着变（这是这份计划里最大的一件事，要用户定，见 §6.1）

百叶后面要是「一镜到底的第一帧」，一镜到底就得紧跟在 hero 后面。现在夹在中间的 Location 和 Masterplan 要挪位置。

**推荐的新顺序：**

1. Hero + 一镜到底（合成一段：百叶 → 鸟瞰 → 大门 → … → Homes → Villas）
2. 收尾：百叶再合上一次（纸色回到深色，和开头呼应；复用同一套百叶，反着放）
3. Location（深色，原样）
4. Masterplan（深色，原样）
5. Enquire 表单（深色，分段页面里现成的那一段）
6. Footer

跟着要改的：

- 一镜到底现在的开头（正上方看平面图、再翻下来，约 2 屏）拿掉，换成 hero 的鸟瞰直接降到大门。「239 homes on 12 acres」那条标注挪到下降这一段。
- 表单现在是在 Villas 那一站从画里升起来的。挪到页面最后（Masterplan 后面）更合理；Villas 那一站只留一个「Register →」。**这改了用户之前定的「表单在结尾」的具体位置（仍在全页结尾，但不在画里了），要确认。**
- 菜单顺序改成：Facilities ▾ · Residences ▾ · Location · Masterplan · Register（跟新顺序走，下拉不变）。
- 之前记着的缺口「Masterplan → 一镜到底的衔接没有对齐」自然消失（两者不再相接）。

**不想动顺序的话（备选）：** 顺序保持 Hero → Location → Masterplan → 一镜到底。百叶后面放一张**只画一次**的鸟瞰（进站时用同一个世界、此刻的太阳渲染一帧，拷成图片后立刻释放显卡资源），穿过窗子以后还是现在那样暗下去接 Location。便宜很多（不动一镜到底、不动菜单），但「穿进画里」就没有了，颜色会是 深 → 纸 → 深 → 深 → 纸。

## 3. 做法（给 Opus）

涉及的文件：`src/components/Hero.jsx`、`src/ink/Take.jsx`、`src/ink/take-route.js`、`src/ink/path.js`（不用改，`shift` / `keep` 已有）、`src/components/Navbar.jsx`、`src/App.jsx`、`src/ink/estate.js` 或新的 `src/ink/far.js`（远景装扮）、`tools/ink/still.cjs`。

### 3.1 百叶拆出来

- 把 `Hero.jsx` 里的百叶（`.louvres`、开合、波、鼠标掀动、`skyAt` 给的金属反光）拆成 `src/components/Louvres.jsx`：输入是一个 0–1 的「开了多少」和一个「准备好了没有」，不自己读滚动。
- 新 hero 不再有 `.hero-light`、`.hero-behind`、`.hero-veil`。
- 分段页面（`?sections`、减少动态、没有 WebGL）还要用 hero：同一个 `Louvres` 盖在一张**静态鸟瞰图**上（见 3.5），百叶直接是开的。

### 3.2 hero 并进一镜到底

- `Take.jsx` 的 `section` 前面加出 hero 这一段的滚动量（约 1.5 屏）。`tk-stage` 是 sticky 的全屏画布，`Louvres` 和窗台作为它上面的两层 DOM（z 在画布之上、标注之下）。
- `take-route.js`：`KEYS` 开头换成 hero 的鸟瞰关键位（带 `shift` 把画抬进窗子）、一个几乎相同的位（那 3% 的慢推），然后接现有的第 3 个关键位（`eye: [-18, 30, 215]`）往大门走。删掉 `id: 'plan'` 的俯视位和它后面那一位；`ANCHORS.about` 改指 hero。
- 镜头远时渲染距离：`stage.js` 里 `FAR = 400`，鸟瞰的眼睛到园区最远角不能超过它（上次就是超了画不出来），调关键位时量一下。
- 百叶开合、窗台滑走由 `Take.jsx` 的 `draw(s)` 按 `s` 驱动（和标注同一个时钟），不另挂 scroll 监听。
- 第一帧准备好（`estate` 和远景装扮两个分块都搭完、渲染过一帧）之前 `Louvres` 保持关着；准备好以后放那道波。预加载幕（`Preloader`）照旧。
- 菜单：`Navbar.jsx` 现在是「菜单压在 `.take` 上就变纸色」。hero 阶段菜单压着的是深色百叶，要保持深色：`Take.jsx` 在窗台还没滑走时给 `section` 加一个标记（例如 `data-cover`），`Navbar` 看到就不变纸色。

### 3.3 远景装扮（新分块）

- 一个 `far` 分块：泳池谷的水面线和岸线、沿谷两侧每隔一段一棵树（用 `adapter.js` 导出的 `treeGeometry`，数量要少）、每户屋顶的露台线、立面上两三道横线。**只用线（`addLines`），尽量不加面**，显存才小。
- 只在镜头高于约 60 m 时存在；降到大门前释放（那时近处的分块开始搭）。
- 显存预算照旧：手机 390×844 整页峰值 ≤ 120 MB（现在 115 MB，峰值在路线中段，不在开头；开头只有体块，大约 40 MB，装扮有余量，但要量）。

### 3.4 收尾的百叶

- 一镜到底最后 0.6 屏：同一个 `Louvres` 从全开转回关上，盖住 Villas；菜单回到深色。之后是普通的深色页面（Location）。
- 表单从 `Take.jsx` 里拿出来（`EnquireForm` 的 `compact` 用法删掉或留给别处），`App.jsx` 在 Masterplan 后面放 `<Enquire />`。`ANCHORS.enquire` 删掉，`#enquire` 回到 `Enquire` 自己身上。

### 3.5 静态鸟瞰图（后备）

- `tools/ink/still.cjs` 加一个 `estate` 选项：用同一个世界、hero 的关键位、固定上午 10:30 的太阳出一张 `public/drawings/estate-ink.webp`（另出一张 jpg 给不支持 webp 的情况，照 homes / villas 的做法）。
- 用在：分段页面的 hero；WebGL 起不来时。
- 这张是**我们自己画的图**，可以进仓库；开发商的效果图和手册照旧不进。

### 3.6 `App.jsx`

```
一镜到底版： <Take />（含 hero 和收尾）→ <Location scrub /> → <Masterplan /> → <Enquire />
分段版：     <Hero />（静态鸟瞰 + 开着的百叶）→ 其余原样
```

`Hero.jsx` 的 `push` 模式整个删掉。

## 4. 做的顺序

每一步：`npx eslint src` 干净、`npx vite build` 通过、截图看过、提交、推分支（`claude/zoom-in-restructure`）。**不要在拍片时改被 Vite 服务的文件。**

1. **样片（先给用户看，说好再往下）**：`sample.html?hero`——`Louvres` 拆出来；hero 鸟瞰关键位 + 远景装扮；百叶开 → 全开 → 窗台滑走 → 降到大门前为止。不动正式页面。交付：桌面和手机各一段逐帧拍的视频、三张截图（关着 / 半开 / 全开）、手机显存数字。
2. 用户说好后：并进 `Take.jsx`，换掉一镜到底的开头，`App.jsx` 改顺序，菜单顺序和 `data-cover`。
3. 收尾的百叶；表单挪到最后。
4. 后备：`estate-ink` 静态图；分段页面的 hero；减少动态。
5. 整页验证：手机 / 桌面逐站截图；`gpu-budget.cjs 390 844`（≤ 120 MB）；`?sections`、减少动态、菜单每一项和下拉每一站都落在对的地方；页面上没有项目名、没有开发商的图；仍然标着 unofficial concept。
6. 整页拍片（桌面 + 手机），更新预览（https://claude.ai/artifact/Jre1pSm1Pru5rPTjEi9nTn）。
7. 清理和文档：删 `Hero.jsx` 里不用的部分；更新 `docs/animation-plan.md`、`docs/world-plan.md`、`.claude/skills/ink-drawing/SKILL.md`。

备选方案（不动顺序）只做第 1 步的一部分（`Louvres` + 只画一次的鸟瞰）加第 4、5、6 步。

## 5. 不确定的地方

- **第一帧要等多久。** 现在一镜到底在页面中段，搭世界的时间藏在前面几屏里；挪到首屏以后，用户进站要等 `estate` 分块搭完才能开百叶。软件渲染里量不出真机的时间。百叶关着当盖子能遮住这段等待，但如果真机上超过两三秒，要先显示静态鸟瞰、搭好再换成活的（两张图太阳方向不同，换的时候影子会跳一下，要用淡入盖过去）。**样片做完请用户在手机上开一次。**
- **只有体块 + 线的鸟瞰够不够好看**，要看了样片才知道。不够的话加面（树冠、水面的点），显存跟着涨。
- **高度都是估的**（来自一张很小的剖面草图），鸟瞰里看得最清楚；页面上那句「Heights… are our reading」要在 hero 阶段就能看到。
- **真机帧率**没量过。
- 页面总长：现在约 43 屏（一镜到底约 32 屏）。这次 hero 2.5 屏并掉、开头的俯视 2 屏删掉、加 1.5 屏 hero 和 0.6 屏收尾，大约少 2 屏。整页还是长，要不要整体缩短是另一件事（§7）。

## 0. 用户的话

> 「你的 transition 怎么看起来差不多的？你有没有看到他们的 masterplan 到底怎么排的？先让 fable 看看 and plan」

两个问题都成立：

1. **过渡都一样**：现在八个地方排成一条直线，每两个之间放的是**同一个模板**（`world.js` 的 `walk()`：一条步道、两道绿篱、一排树、一排别墅），镜头每次也是同一个动作（升到 8 m、往右平移、降下去）。同一段东西重复了七次。
2. **没照总平面图排**：我上一轮说「这些地方之间真实是什么样，资料里没有」，这句话是错的。手册第 5 页（设施总平面）、第 10 页（单位编号总平面）、第 3 页（整个园区的鸟瞰）、第 12 / 16 页（剖面）把布局、楼层、每样设施在哪都画出来了。我只描了八张效果图，没有去读这几页。

**结论：不要再「想象中间」。世界就是总平面图。** 每一站放回它在图上的真实位置，镜头沿着图上真的能走的路走；路过什么，图上写的就是什么。这样每一段过渡天然不一样，因为每一段经过的地方本来就不一样。

不做的事（照旧）：不动 `main`、不上线；不用开发项目的名字和 logo；手册的图（原图或裁切）不进仓库、不上网站——只把**读出来的数**写进代码；不编事实，估的要写明是估的。

## 2. 做法

### 2.1 底图从哪来：网站里那张 Masterplan SVG

`src/components/Masterplan.jsx` 里那张 SVG（`viewBox="0 0 516 789"`，877 个图元）本来就是照手册第 5 页描的矢量图，而且**每样设施一个带 id 的组**（`aqua-lb2-a` … `aqua-lb2-w`、`aero-l2-*`、`aero-lg-*`）。不用重新描。

新文件 `src/ink/site.js`：把这张 SVG 变成世界的数据（米）。

- 比例 **k = 0.39 m / SVG 单位**（附录 A：别墅每户 8.4 m 和 Homes 每户 12.8 m 两个手册里的数各自量出来是 0.391 和 0.388，对得上）。
- 坐标：`x = (svgX − 259) × k`（东为正），`z = (svgY − 392) × k`（南为正，所以**北 = −z**），`y` 向上，泳池谷底 = 0。
- 导出：地块（五条带里每一户的矩形）、车道带、桥（斜的四边形）、泳池的轮廓（两段水面）、每样设施的轮廓和一个标注点（从它那个 id 的组里取）、大门和大堂、场地边界。
- SVG 的几何从组件里搬到一个数据文件，`Masterplan.jsx` 和 `site.js` 都从那里读，免得两处各一份。

**核对工具**（先做这个）：`tools/ink/site-overlay.cjs`，把 `site.js` 的数据画在 SVG 上，再叠在手册第 5 页的裁切图上（裁切图只在 scratchpad），截图看对不对。和之前叠人行桥那张图是同一个做法。

### 2.2 哪些用现成的画，哪些只画体块

**有效果图的，用现成的画，放回真实位置**（都是现有的函数，改成按 `site.js` 的位置和朝向放）：

- 两条内排朝泳池的立面：`villaRow`（`tools/drawings/scenes/villas.js`），按 6 / 10 / 6 分组，中间留连廊。
- 内排朝车道的那一面 + 车库口 + 桥：人行桥那张图里的 `villa()`、挡土墙、车库口、`fence()`、桥面（`walkway.js`，要把这些拆成可以按位置调用的函数）。
- K：`pavilion()` + `treadmill()`（`gym.js`）；J：`cabana()`（`gym.js`）。
- D：休憩平台和两个「巢」（`lounge.js`，拆成函数）。
- Q 的船、I 的岛、喷泉：`aerial.js` / `pool.js` 里现成的。
- 大门：`entrance.js` 的门楼和门卫亭。
- 两张正面图那一户：`homes.js`、`villas.js` 的整栋，放在路线停的那一户上；同一排其余的户，Homes 用体块（淡），Villas 就是 `villaRow`。

**泳池的轮廓不再用每张图各自画的那个**，统一用 `site.js` 里从总平面图来的轮廓（现在 pool / aerial / gym 三张图各画了一个不一样的泳池，放进同一个谷里会打架）。

**没有效果图的设施**（B、C、E、H、L、M、N、O、P、S、T、U、V、W，步道层的 A、B、C、D、E、F、G、H）：只画**总平面图上的轮廓拉起来的体块**（淡线、平的，和现在的「ghost」一个画法），旁边钉一个小标签，写的就是总平面图图例里的字母和名字（「O · Jacuzzi Retreat」）。它们长什么样手册没给，所以不画细节。

镜头规矩照旧：一条连续的路线（`Flight.jsx` 现有的向心 Catmull-Rom + 按弧长平滑速度都留着），每张描过的图只在它描图的那个角度附近看；两张正面图最后落在和原图一模一样的画面上（`square()`）。

### 2.4 太阳：用真实的方位

以前不知道房子朝哪，所以光永远放在画面前方（`light.js` 的做法）。现在总平面图上有指北针，**世界有了真的东南西北**，太阳可以放在它真实的方位上：早上从东边照过来，西内排朝泳池的那一面是亮的；下午反过来。Hero 那句「the sun is … to the west-southwest」和图里的影子就真的对上了。

- 方位用 `sun.js` 的真实方位角；高度照旧夹在 14°–52°（太低全是长影子，太高每个凹处都是黑的），页面上照旧说明夹了。
- 代价：某些时刻，停下来看的那一面正好背光。这是真的，玻璃照旧留白，墨点照旧画阴影。
- 分段页面（后备）里那两张可以拖太阳的卡片不改，还是原来的画法。

### 2.5 页面怎么接

- **Masterplan 那一段（2D，逐个点亮设施）→ 一镜到底**：一镜到底的第一帧就是**同一张平面图，正俯视，画成墨线**，位置和大小对齐 Masterplan 那张 SVG 在屏幕上的位置；然后镜头压下去，平面图立起来。深色底换成纸色就在这一下完成。
- **角上一张小地图**（就是那张 SVG 的轮廓，很小）：一条线是路线，一个点是镜头现在在哪、朝哪。走到哪一目了然，也让人看得出这条路是照图走的。手机上放在右下，可以点一下收起来。
- 其余不变：窗子、槟城岛到地块、平面图钉住的那段、后备的分段页面、`?sections`、太慢时的提示。

### 2.6 分块和性能

世界比现在大（四排别墅 + 一排 Homes，每排二十多户），但做法不变：`stage.chunk / drop`，镜头附近才建，后面立刻放。

- 按路线切块：Homes 排（南 / 中 / 北）、西车道带（南 / 中 / 北）、泳池谷（北 / 中 / 南）、南端、东边两排（只在高空和谷里远远看到，用体块，不用细立面）。
- 远处用体块、近处才换成细立面（同一个地块两种画法，按距离换；换的时候两者轮廓一致，所以不跳）。
- 预算照旧：`tools/ink/gpu-budget.cjs`，手机整页峰值 ≤ 120 MB，涨了要回来；真机帧率要用户自己滚一遍。
- 第 0 段的整园区鸟瞰是最重的一帧（所有地块都在画面里）：全部用体块，线用最细的一档。

### 2.7 页面上怎么说

- 拿掉「The walk between these places is imagined…」。
- 换成一句常驻的小字（和那行时间放一起）：**"Laid out from the developer's masterplan. Heights, and which home or bridge each drawing shows, are our reading."**
- 路过的设施标签用总平面图图例里的原名（字母 + 名字），不加形容。
- 八个主要的标注（数字、户型、价格）照旧，只用网站已有的内容。

## 3. 做的顺序

每一步：`npx eslint src` 干净，`npx vite build` 通过，截图看过，提交、推分支。**第 3 步做完先给用户看，说好再往下。**

1. **`site.js` + 核对图**：SVG 几何搬成数据，换算成米，`site-overlay.cjs` 叠图核对。交付：叠图截图。
2. **体块世界**：只用 `site.js` 的体块（地块按层高拉起来、车道三层板、桥、泳池轮廓、绿墙、大门体块），正俯视和斜鸟瞰各截一张，和手册第 3 页的鸟瞰比。还不放细立面。
3. **样片：第 4–7 段**（绿墙降下来 → 平台 → 泳池 → Villas 正面 → 穿过健身房）。这是最能看出「照图走」的一段，也是现成的画最多的一段。交付：桌面和手机各一段逐帧拍的视频 + 预览 + 显存数字。**等用户说好。**
4. 其余各段：0–3（鸟瞰、Homes、桥、步道）、8–10（鸟瞰构图、南端、大门 + 表单）。
5. 真实方位的太阳（§2.4）；小地图；Masterplan → 一镜到底的衔接（§2.5）。
6. 整页验证：手机 / 桌面逐站截图、`gpu-budget`、减少动态、`?sections`、锚点；整页拍片；更新预览。
7. 清理：删掉 `world.js` 的 `walk()` 和直线排布；更新 `docs/animation-plan.md`、`.claude/skills/ink-drawing/SKILL.md`。

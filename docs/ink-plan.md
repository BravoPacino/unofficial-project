## 0. 要做成什么

把 Courtyard Homes 画成一张「上了墨」的图，放进我们自己网站的版面里。三个要求，按重要性排：

1. **画法和 Heron 一样**（heronaiapp.com 首屏那张楼）。只要画法，画的是我们的房子。
2. **房子像宣传图**。现在「稍微有点不像」。
3. **玻璃看得出是玻璃**。现在看不出。

不做的事：

- **不抄 Heron 的版面**。格子、页边刻度尺、四角的十字、标题条、`[01]` 注释栏都不要。

- 不把开发商的效果图（原图或裁切）提交进仓库。参考图只放在仓库外面。
- 不编事实。文案只写效果图上看得见的东西；尺寸都是按图估的，要这么说。
- 网站仍然是 unofficial concept，不能看起来像开发商官方的东西。

工作方式（用户的规矩）：回复用中文、简短；先找出问题再改，别一路试；自己验证过再说做好了；
做好了要发预览给用户看；用户没说开始的事不要开始。

## 3. 三个问题，原因在哪

### 3.1 房子不像宣传图

把模型轮廓叠到宣传图中间那栋上量的（`tools/ink/overlay.cjs`，按白框左右边对齐）。左右基本对得上，错在高度、一楼和深浅：

- **整栋矮了约 14%**。按白框宽 7.7 m 当尺子，宣传图从框顶到地面约 12.3 m，模型只有 10.6 m。
  白框本身矮约 0.65 m（宣传图里接近正方形）；一楼矮约 1 m。
- **一楼画宽了**。宣传图里一楼和上面差不多宽，只有那排木条往右挑出去约 2 m，底下是空的。
  模型把一楼做成更宽的台子：左边多约 1 m，右边多约 1.5 m。
- **木格栅那格宽了约 0.2 m**，阳台那格相应窄了。
- **深浅关系不对**。宣传图里右边那条塔几乎是黑的、凹进去的墙是中间调、木头是中浅调。
  模型里塔是中灰（`NAVY = 0.46`），木头几乎是白的（`TIMBER = 0.93`）。
- **只画了一栋**。宣传图是一排，邻居的深色侧墙也是「像」的一部分。

具体数字在附录 A。绝对尺寸不知道，只保证比例照图。

### 3.2 玻璃不像玻璃

1. **玻璃和墙用的是同一种颗粒**。一楼整片玻璃在楼板的影子里，印出来约四五成墨，和旁边影子里的白墙几乎一样。
   Heron 那里玻璃是纯纸白，一粒点都没有。
2. **没有深度**。正交立面里，窗洞的顶和侧壁都是侧对着的，看不见。
   Heron 是一点透视，每组玻璃外面都有一圈深色的顶和侧壁，角上是斜线，一看就是「里面是空的」。
3. **里面什么都没有**。Heron 隔着玻璃能看到矮墙、隔断；宣传图一楼能看到楼梯、家具、竖木格屏。
4. **竖梃没有性格**。和别的线一样粗细，也被栏杆线、百叶线淹掉了。

### 3.3 版面

`Sample.jsx` 整页是照 Heron 的图纸版面做的。用户只要画法，这一层不要。

## 4. 怎么做

按顺序。每一步做完先自己验证，再发图给用户。

### 第 1 步 · 相机换成一点透视（`stage.js`）

现在是 `OrthographicCamera`。换成 `PerspectiveCamera`，正对立面、不仰不俯，用不对称视锥（建筑摄影的移轴）让竖线保持竖直。

- 相机放在 `(cx, eyeY, D)`，朝 −z 看，不旋转。起始值 `eyeY = 1.7`、`D = 26`，之后叠图微调。
- 取景仍然按「立面所在的 z = 0 平面上露出哪一块」来定，和现在的 `VIEW` 一个意思：
  横向 `cx ± W/2`，竖向 `yb … yt`（`yt − yb = W · h / w`，中点是 `cy`）。
- 近平面 `n` 上的视锥边界：
  `left = −W/2 · n/D`，`right = W/2 · n/D`，`top = (yt − eyeY) · n/D`，`bottom = (yb − eyeY) · n/D`。
  用 `camera.projectionMatrix.makePerspective(left, right, top, bottom, n, far)` 直接写矩阵，
  同时更新 `projectionMatrixInverse`，不要再调 `updateProjectionMatrix()`（会把它冲掉）。
- `projector(view, w, h)` 现在只接受 `(x, y)`。改成 `(x, y, z = 0)`：先把点沿视线投到 z = 0 平面
  （`s = D / (D − z)`，`X = cx + (x − cx)·s`，`Y = eyeY + (y − eyeY)·s`），再走原来的线性换算。保持纯函数（React lint 不许渲染时读 ref）。
- `InkDrawing.jsx` 里的树、热点、延长线、地平线都经过 `projector`，要给它们各自的 z。树在 2D canvas 上，前排的 z 取正值（在房子前面），画出来会大一点。
- 阴影相机、隐藏线那一遍不用动。

验收：竖线仍然竖直；两格凹阳台各能看见顶棚（一条深色梯形）和一侧侧壁；一楼木条带能看到一点底面。

### 第 2 步 · 按宣传图重定比例和深浅（`homes.js`）

- 尺寸按附录 A 改。附录里是「图上看起来的」数（都按白框所在平面换算的），换了透视相机以后**以叠图为准**微调真实尺寸。
- 一楼收到和上面同宽（约 −5.0 … 4.48）。木条带保持往右挑到约 6.6，挑出去的那段底下是空的。
- 深浅：塔接近黑（灰度约 0.16–0.2，不要到「涂实」的阈值，窗框还要看得见）；凹墙中间调（约 0.45）；
  木头中浅（约 0.72–0.78，亮处约两成墨）；白墙不变。
- 左上角高出框顶的隔墙头、右边高出屋面的白墙片都保留（用户点名要的）。
- 邻居（如果用户选「一排」，见第 5 节）：左右各露半栋，画淡一档。
  「画淡」不能用现在的 `veil`（乘法混合只能压暗）；做法是把邻居的灰度往白压一半（`a' = 1 − (1 − a)·0.5`）、线用 `soft`。

验收：`overlay` 改成用同一个相机投影后，白框四边、中梁、分隔柱、塔、白墙片、楼板、木条带、一楼玻璃两格和地面，
全部对到 10 px 以内（约 0.15 m）。把叠图发给用户。

### 第 3 步 · 玻璃（`stage.js` 加一个 `glazing` 助手，`homes.js` 用）

规则：

1. **玻璃面是纯纸白**：灰度 1、不收影子（`receiveShadow = false`）、不撒点（走现在 `pane` 用的「干净面」标记，蓝通道减半那套）。
   明暗落在窗洞的顶和侧壁上，不落在玻璃上。Heron 就是这样。
2. **玻璃退进墙里 0.15–0.2 m**，窗洞有真的顶、底、侧壁。有了第 1 步的透视，这一圈深色边会自己出现。
3. **竖梃**：细、等距、通高、实心黑；外框比竖梃粗一档。栏杆线和百叶线不能压过它（保持 `hair`，必要时再稀一点）。
4. **透明的玻璃（一楼）**：不放玻璃面，真的建一个房间盒子（地、顶、后墙、两侧墙，都是干净面），让太阳照进去，
   亮的地面、暗的顶棚由渲染器自己算。里面放效果图上看得见的东西的剪影：右格的楼梯、左格的矮家具、两片竖木格屏、约 2.5 m 高的一道横档。
5. **反光的玻璃（阳台推拉门、塔上两扇小窗、木格栅后面那片）**：用规则 1 的白面。

顺序：先只做一格阳台门当试验，和 Heron 的玻璃放在一起比，过了再铺到其余的。

备选，只在以上做完还读不出来时才用：两三条斜的反光带，连续跨过竖梃。
用 `CustomBlending` + `MaxEquation` 把带内的灰度抬到 0.93 以上（先在一格上确认这个混合方式在 MSAA 目标上可用）。Heron 没有用反光带，所以不是首选。

验收：把图缩到 400 px 宽看，能一眼指出哪些是玻璃；玻璃是全图最白的面；用户看过说像。

### 第 4 步 · 去掉 Heron 的版面，放进自己的版面

- `Sample.jsx`：删掉格子、刻度尺、十字、标题条、注释栏。样板页只留画本身和一行说明，当测试页用。
- `InkDrawing.jsx`：给它开关（HUD、热点、延长线各一个），默认值见第 5 节。
- 接进 `src/components/Residences.jsx` 的 Courtyard Homes 卡片，换掉 `homes-ink.webp`。那一章的底色和纸色一样（`#efe8da`）。
  - 进视口才建 WebGL，离开很远就释放（一页里不要同时开几个 WebGL 上下文）。
  - WebGL 起不来时退回现有的静态 webp。
  - `prefers-reduced-motion`：不做回弹动画（已有）。
- 诚实说明留一行，放在图附近：时间是真的；朝向不知道所以光放在正面；太阳高过 52° 按 52° 画。

### 第 5 步 · 验证和交付

- 桌面 1440、手机 390：没有报错、没有横向溢出。
- 互动：拖动改时间、松手回实时、方向键、热点；手机上横拖改时间、竖划照常滚页面（用 CDP 发真触摸，`tools/ink/touch.cjs`）。
- 三个时刻各看一眼：上午、日出前、天黑后（`tools/ink/shot.cjs` 可以固定时间）。
- 构建通过，`npx eslint src` 干净。
- 提交到 `claude/zoom-in-restructure` 并 push，发私有预览给用户。不动 `main`。

**到这里停下，等用户看。** 用户满意以后才做第 6 节。

## 7. 已经踩过的坑

- **纸色发暗**：自己写的 `ShaderMaterial` 输出要加 `#include <colorspace_fragment>`。
- **影子边缘锯齿**：改了 `DirectionalLight` 阴影相机的范围以后要调 `shadow.camera.updateProjectionMatrix()`；范围收紧到模型（现在 ±13 m、4096）。
- **颗粒看起来脏**（用户两次反馈）：随机噪声的颗粒会结团，稀的地方单个点像灰尘。已换成均匀点阵（每格一个圆点，面积 = 深度，轻微抖动），浅灰直接留白，没有零星斑点。不要再换回随机噪声。
- **影子的形状被线盖掉**：栏杆、百叶这类密线一多，颗粒读不出形状。密线用 `hair`，大面留干净。
- **正午凹处全黑**：太阳高度封顶 52°（`light.js` 的 `HIGH`）。页面上要说明。
- **日出前后**：太阳在地平线下时不要写成「天黑」；按日出前 / 日落后分别说（已做）。
- **手机**：窄屏取景收窄（`viewFor`）、线宽按每米像素数缩（`stage.resize` 里的 `k`）、说明卡贴在图底部；
  `touch-action: pan-y` 加上判断方向，竖划要能滚页面。
- **`setPointerCapture`** 可能抛错（指针已经没了），要包 `try`。
- **测试环境是软件渲染**，每帧很慢。启动参数 `--use-angle=swiftshader --enable-unsafe-swiftshader`。真机上拖动顺不顺还没量过。
- **乘法混合只能压暗**。要变淡得改灰度本身。

## 0. 要做成什么

**整页是一个镜头。** 不再是一段一段、一张一张卡片；往下滚 = 镜头往前走。
从窗子（Hero 的百叶）穿出去，落到槟城岛的地图上，扎向地块，变成鸟瞰，然后沿着园区一路走：长泳池 → 人行桥 → Courtyard Homes → Villas → 漂浮健身房 → 休憩平台 → 大门。最后停在大门前，询问表单在那里。

文字不再是段落，**是钉在场景里的标注**：一根墨线从物体上引出来，末端是那句话（「239 homes on 12 acres」「4–6 parking lots per home」……）。

为什么我们做得了、别人做不了：八个场景本来就是真的 3D 模型，墨点是实时算的。现在只拿它们当静图贴在卡片里，浪费了。

不做的事：

- 不动 `main`，不上线；只在分支上做，发私有预览。
- 不用开发项目的名字和 logo；不把效果图、手册放进仓库或网站。
- 不编事实。标注只用网站已有的、来自手册的数和说法；尺寸是估的要照旧写明是估的。
- 光照照旧是 **George Town 此刻真实的太阳**，不为了好看把它改成黄昏。

## 2. 关键做法

### 2.1 一次只活一个场景（守显存，不再闪退）

八个场景**不放进同一个世界**（它们的坐标各是各的，而且每个都只照一个角度描的）。
做法是电影里的「接镜」：每站一个场景，站与站之间用**墨点换场**接起来，看起来像一个镜头。

- 同一时间显存里最多两个场景：当前这站 + 预先建好的下一站。阴影贴图和渲染目标两站共用一份。
- 离开一站就 `dispose()`（`stage.js` 已有完整释放）。
- 预算：用 `tools/ink/gpu-budget.cjs` 量全程滚动，手机（390×844）峰值 ≤ 120 MB，桌面 ≤ 180 MB，而且必须「涨了会回来」。

### 2.2 墨点换场

换场时，上一站最后一帧存成一张贴图（2D 拷贝，很便宜）；下一站开始渲染。
在网点着色器里加一个 `uFrom` 贴图和一个进度 `uMix`：**每一格网点**按一张固定的阈值图决定显示旧画面还是新画面，旧的墨点缩小、新的墨点长大，就像墨重新渗进纸里。
不是交叉淡化，是一格一格的点在换。地图 → 鸟瞰那一次从金点开始往外晕（阈值图用到金点的距离）；其余的顺着镜头前进的方向扫过去。

### 2.3 镜头

- 每站写一条镜头路线：几个关键位 `{ eye, at, fov }`，用 Catmull-Rom 插值，滚动进度 → 路线上的位置。`stage.js` 现在只在 `resize` 时设相机，要加一个 `setLook(look)`，每帧只改相机，不重建任何东西。
- **镜头只能在描图的那个角度附近动**（前后推拉、左右 ±20°、上下一点）。每个场景是照一张效果图的一个角度描的，绕到背后就会露出没建的面。每条路线都要用 `tools/ink/shot.cjs` 截路线上的 5 个点检查。
- Homes 和 Villas 现在是正面相机（`homes.js` / `villas.js` 的 `VIEW`）：「走」的那段用斜相机进场，「停」的那段落到正面相机上。两种相机之间的过渡用 fov 和位置一起插值，最后一帧和现在那张图完全一样。

### 2.4 太阳不能跟着镜头转

现在 `stage.js` 把光「放在看的人前面、往旁边偏」（光的方向是相对相机算的）。镜头一动，影子就会跟着滑，一眼假。
**改成：每一站进场时按那一站的「停」的镜头算一次光的世界方向，整站固定不变。** 阴影贴图在一站里只算一次（`sun.shadow.autoUpdate = false`，光变了才 `needsUpdate`），每帧省掉一大块。

### 2.5 标注

- 标注是真的 HTML（读屏和搜索照样读得到，顺序就是页面顺序）。
- 每条标注挂在一个世界坐标上，每帧用当前相机投影到屏幕（`project.js` 已有纯函数投影），一根墨线（SVG）从那一点引到文字。
- 「停」的时候一条条画出来（墨线 `pathLength` 画线，文字 `SplitText` 浮起）；「走」的时候收起。
- 标注不能盖住主体：每条标注给一个首选的屏幕侧，投影后撞到主体的包围框就换另一侧。

### 2.6 帧

- 只有滚动在动的时候才渲染（现在的墨图是一分钟画一次，这里改成滚动时每帧画、停了就不画）。
- 走的时候用较低分辨率（DPR 1，网点格按比例放大，看起来一样），停下的那一刻用全分辨率补画一帧。
- 目标：中端手机走的时候 ≥ 40 fps；滚动期间长任务（> 50ms）为 0。建下一个场景的时候不能卡（建场景要拆成几帧做，或在「停」的那段里空闲时做）。

### 2.7 不能跑的时候

**现在这个分段的页面整个保留，当作后备。** 以下情况都用它：

- 打开了「减少动态」；
- WebGL 起不来；
- 前几帧测出来太慢（比如前 10 帧平均 > 45ms）。这种情况下页面角上给一个「切换到简洁版」，不偷偷切。

所以后备版不是简陋版，是现在已经做好的整站，信息一样不少。

## 3. 先做样片，再做整站

**样片（约 10 秒的滚动）：** 第 2 → 3 → 4 站，鸟瞰往下压 → 墨点换场 → 贴着长泳池滑 → 墨点换场 → 掠过人行桥。带两三条标注。

样片要回答的问题：

1. 一镜到底在我们的墨画法里好不好看？（主观，给用户看）
2. 墨点换场像不像「一个镜头」？
3. 手机能不能带：显存峰值、帧时间（真机为准；swiftshader 的 fps 偏慢很多，只看长任务数和显存）。

样片交付：录屏（Playwright `page.video`，390×844 和 1440×900 各一段）+ 预览链接 + 显存和帧的数字。
**用户看过样片说好，才做整站。**

样片已做（`src/ink/Flight.jsx`，`sample.html?flight`；拍片 `node tools/ink/film.cjs <out.mp4> [W H] [秒] [fps]`）。和上面计划不同的两处：
- 一路上每个场景**全画**（不用配套图的 focus 把周围变淡，淡了一路看过去很空），但**树只留主体范围内的**：镜头正前方的 3D 树会变成横过画面的黑树干。
- 换场的格子约两颗墨点大（`W/260` px），看起来是两张图在换墨点，不是像素块。
手机（390×844）显存峰值 108 MB，滚完会回落。帧率要在真机上量。

整站的顺序：路线和站（2.1、2.3、2.4）→ 换场（2.2）→ 标注（2.5）→ 0、1 站（窗子、地图，2D 的部分）→ 5、6 站（Homes / Villas 落到正面）→ 7、8、9 站 → 后备切换（2.7）→ 全程验证。

每一步：`npx eslint src` 干净；`npx vite build` 通过；`gpu-budget.cjs` 量一遍；减少动态模式截一遍；提交、推分支、更新同一个预览 artifact。

## 5. 已经踩过的坑（相关的）

- 每张墨图都占着显存不放 → 手机滚到图就闪退。现在是画完即放；一镜到底必须守「最多两个场景」。
- 光是相对相机算的（见 2.4）：镜头一动影子会滑，必须先改成每站固定。
- 场景只照一个角度描：镜头偏太多会露馅（见 2.3）。
- swiftshader 里的帧率不代表真机；量的时候看长任务和显存，最后要用户在自己的手机上试。

### 7.1 一个世界（用户：「还是不够顺……中间有什么你直接画出来，那些车直接 remove」）

- 墨点换场拿掉了。八个地方放进**同一个世界**（`src/ink/world.js`），沿 x 排开，都朝原来描图的方向（−z），所以一个太阳照全部；每两个地方之间 50 m 画一段**想象的花园步道**（铺地、矮绿篱、一排树、一排别墅），在画面上写明「The walk between these places is imagined. The real layout is in the masterplan.」
- 镜头是**一条连续的路线**：所有站的关键位 + 每段步道两个关键位，向心 Catmull-Rom，速度按弧长做平滑（不会一段快一段慢地跳）。
- 世界分块（`stage.chunk / drop`）：镜头附近大约三个地方 + 它们之间的步道，后面的立刻释放。手机整页峰值 50 MB（这次连几何体缓冲一起算）。
- 车：`adapter.js` 的 `car()` 什么都不画，所有图都没有车；入口和人行桥的后备静图重出了。

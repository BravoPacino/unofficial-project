# 动画计划 · 整站

写给接手执行的人。这份只是计划，代码还没按它改；用户 confirm 之前不开始。
分支 `claude/zoom-in-restructure`，写这份计划时的提交是 `6958d24`。

---

## 0. 要做成什么

用户的话：「plan 一下我们的整个 animation，make it wow」。

**一条主线：** 这个网站跟别的楼盘网站不同的只有两样东西：**George Town 此刻真实的太阳**，和**自己上墨的图**。
所有「wow」都从这两样长出来，不加和它们无关的特效（不加粒子、不加 3D 飘浮、不加乱闪的文字）。

一句话：**墨一笔一笔画出来，太阳一天走过去，最后停在「现在」。**

不做的事：

- 不动 `main`，不上线。用户说「上线」之前只在分支上做，发私有预览。
- 不用开发项目的名字和 logo；不把效果图、手册放进仓库或网站。
- 不编事实。动画里出现的数字（距离、面积、户数）只用网站已经有的、来自手册的数。
- 不劫持滚动：除了下面列出的几段钉住（pin），滚动就是滚动。

## 2. 七个时刻（按页面顺序）

每个时刻写：**看到什么 · 怎么做 · 手机 · 减少动态（reduced motion）**。

### M0 · 开场：百叶是画出来的（Preloader → Hero）

- **看到：** 黑底上，一根根细金线从上往下画出来（就是 Hero 那排百叶的位置，错开 40ms）。线画齐后，标题在百叶上显出来，然后线「长厚」成百叶，光从缝里透出来。**没有帘子，Preloader 直接变成 Hero。**
- **做法：**
  - Preloader 不再盖一层帘子；它在 Hero 的百叶位置上画同样数目的竖线（`geom.N`，从 Hero 拿同一个算法）。
  - 用 `scaleY` 0→1（`transform-origin: top`）画线；画完 `onLift`，Hero 的 `.louvre` 从线宽 tween 到真宽，`.hero-light` 淡入（现在已有 1.6s 淡入，接上即可）。
  - 字体等待逻辑不变（`MIN_HOLD` 改成「线画完」为止，约 1.4s）。
- **手机：** 一样，线少（N 本来就随宽度变）。
- **减少动态：** 直接显示 Hero，不画线。

### M1 · 穿过窗子（Hero → 01 Idea）

- **看到：** 百叶开到底之后继续滚，镜头往窗里推，窗框放大出屏幕；窗后的天光褪成纸色，纸色就是 Idea 的底色，Idea 的标题从纸上浮起。**黑 → 纸，是穿过去的，不是切过去的。**
- **做法：**
  - `.hero` 从 200svh 加到 260svh；百叶打开占前 0–0.55，推镜占 0.55–1。
  - 推镜：`.hero-window` `scale` 1→3.2（以窗中心为原点），`.hero-light` 的背景插值到 `#efe8da`（Idea 的 BG），百叶透明度 →0。全用 `transform` / `opacity` / 一个覆盖层的 `background-color`，不重排。
  - Idea 的第一屏不需要再「淡入」，它已经在纸上了：Idea 头部的 `SplitText` 在 Hero 进度 0.85 时开始。
- **手机：** 一样；推镜倍数 2.4。
- **减少动态：** 现状（百叶静态，正常往下滚）。

### M2 · Idea：墨线落在纸上

- **看到：** 标题一行行浮起（已有）。三根柱子（Nature / Leisure / Space）上方各有一道细墨线，从左往右画出来；编号 01/02/03 跟着线头出现。数字计数保留。
- **做法：** 一个 `<i class="idea-rule">` 用 `scaleX` 0→1，ScrollTrigger `start: 'top 75%'` 一次性播放。小动作，不抢戏；wow 在前后两段。
- **减少动态：** 直接显示。

### M3 · Location：从岛到地块（钉住，约 2 屏）

这是 restructure B 欠下的「岛 → 地块」放大，在这里一起做。

- **看到：**
  1. 槟城岛的海岸线**一笔画出来**（从 George Town 起，绕岛一圈），对岸的海岸线淡淡跟上；
  2. 镜头往 George Town 推，地名按大小一级一级出现（`names` 里的 `r` = 3 → 2 → 1 → 0）；
  3. 世遗区那块铺上墨点（和墨图同一种均匀网点）；
  4. 地块位置出现一个金色的点（就是 Hero 那个太阳的颜色），从它往外推出几道同心距离圈；
  5. 附近地点一个个点亮，公里数从 0 跳到真实值（`pois[].km`，已在数据里）。
- **做法：**
  - 地图已经是 SVG 数据（`src/data/penangMap.js`：`island`、`coast`、`heritage`、`names`、`pois`）。海岸线用 `pathLength="1"` + `stroke-dasharray: 1` + `stroke-dashoffset` 1→0，随滚动 scrub。
  - 推镜：改 `<svg>` 里一个 `<g>` 的 `transform`（scale + translate 到 George Town），不改 viewBox（改 viewBox 会每帧重排文字）。
  - 网点：SVG `<pattern>` 圆点，和 `stage.js` 的网点同大小（约 2.2px 一格）。
  - 钉住：`ScrollTrigger` `pin` + `scrub: 0.6`，长度 `+=180%`。
- **手机：** 同样钉住；地图占上 60%，地点列表在下面跟着点亮。
- **减少动态：** 最终状态的静态地图。

### M4 · Masterplan：平面图自己画出来（缩短到约 2 屏）

- **看到：** 进屏时，平面图的线**画出来**（1.2s，按区域错开），然后进入现在的钉住点亮；被点亮的区域**铺上墨点**并有一道细金描边，而不是换一个平色。
- **做法：**
  - 69 个 `<path>`/`<polygon>`：同 M3，`pathLength="1"` 画线，`IntersectionObserver` 一次性播放（不 scrub，平面图不应该跟着来回倒）。
  - 点亮：`.interactive-group.active` 的 `fill` 换成和 M3 同一个网点 `pattern`；加 `stroke: #c8a86b`。
  - 钉住长度从 `total × 130px` 改成固定 `+=200%`，`activeCount` 用进度算（总数不变）。
- **手机：** 现状的「列表滑过一条线点亮」保留，只加画线和网点。
- **减少动态：** 平面图直接完整，点亮照常（那是信息，不是装饰）。

### M5 · Residences：一天走过这栋房子（全站最大的一个 wow）

- **看到：** 房子卡片第一次进屏时，太阳从**日出走到日落**（约 3 秒），影子在立面上扫过去；左下的时间读数跟着跳（比如 7:0x am → 7:1x pm，用 `sun.js` 算当天真实的日出日落，不写死）。走完之后**回到此刻**，停下，旁边出现一行小字：「拖动，换一个时间」+ 一个小太阳图标往左右晃一次。Villas 卡片在 Homes 走完之后、自己进屏时再走一次。
- **做法：**
  - `InkDrawing.jsx` 已经有「拖动 = 时间偏移」和「松手漂回现在」。加一个 `sweep()`：用 GSAP tween 那个偏移量（从日出到日落，再 ease 回 0），每帧照常 `render`。
  - **只在第一次进屏放一次**（`once`），之后只有拖动。两张卡排队，同一时间只有一张在每帧渲染。
  - 帧率：扫的过程中把 DPR 降到 1、`uCell` 按比例放大保持网点大小，走完那一帧用全分辨率补画一次（扫的时候看不出差别，GPU 省一半以上）。
  - 太阳太低时（`light.js` 里有 LOW 14° 的夹紧）影子会很长：日出、日落两端各让 0.3s，免得一开始全黑。
- **手机：** 一样放，但用 DPR 1 全程；扫的时间 2.4s。
- **减少动态：** 不扫，直接是此刻；提示文字照常显示。

### M6 · Facilities：每张图「上墨」（横向轨道里）

- **看到：** 横向滑动时，每张配套图进到舞台里就**被画出来**：先是线（顺着滑动方向从左往右出现），然后墨点和影子从**太阳那一边**洗过来，最后金色太阳圆从下面升到它的位置。之后是静的（现在已经是：一分钟重画一次影子）。
- **做法：**
  - `InkPlate` 在同一个排队的任务里画两层：**线层**（只画线那一遍）和**墨层**（网点 + 影子那一遍），分别拷到两张 2D canvas。`stage.render(dir, { only: 'lines' | 'tone' })` 加一个参数即可，三遍本来就分开。
  - 显现用 CSS：线层 `clip-path: inset(0 100% 0 0)` → `inset(0 0 0 0)`；墨层用 `mask-image` 的线性渐变，从太阳那一侧扫过（方向从 `light.frac` 来）；太阳圆单独一个 `<div>`，`translateY` 升起。只有 `clip-path` / `mask-position` / `transform`，不重画 WebGL。
  - 显现完立刻把两层合成回一张 canvas、释放另一张（守 GPU / 内存预算，见 §3）。
  - 触发：卡片中心进入舞台右边 70% 时（用轨道的进度算，不用 IntersectionObserver，因为卡片是横移的）。
- **手机：** 一样。
- **减少动态：** 画好直接显示（现状）。

### M7 · Enquire：太阳落下之前

- **看到：** 入口墨图做底，随滚动慢慢推近（scale 1→1.06，scrub）。表单字段一行行升起。表单下面一行小字：「今天 George Town 的日落是 …」（真实值，`sun.js` 算，不写死）；如果已经天黑：「明早 … 日出」。
- **做法：** 都是 `transform` + 一行文本，`sun.js` 已有日出日落计算所需的东西（如果没有直接的函数，加一个 `sunTimes(date)`，用同一个太阳位置公式二分找高度 0°）。
- **减少动态：** 不推近；文字照常。

### 贯穿全站

- **章节底色：** 黑（Hero）→ 纸（Idea）→ 深（Location / Masterplan）→ 纸（Residences / Facilities 的墨图都在纸上）→ 深（Enquire）。底色切换在两段之间**用滚动插值**（覆盖层 `background-color`，0.4 屏的过渡），不是硬边。
- **光标：** 在墨图上变成一个小太阳（金色圆点），提示可以拖。只桌面。
- **导航：** 章节号 01–06 在导航里随滚动「翻牌」（`yPercent` 换一位）。

## 3. 规矩（每一个时刻都要守）

1. **只动 `transform`、`opacity`、`clip-path`、`mask-position`、覆盖层颜色。** 不动 `width/height/top/left`，不在滚动里读布局。
2. **同一时间只有一个 WebGL 在每帧渲染**（M5 的扫），其余墨图仍然「画完即放」。
3. **显存预算：** 用 `tools/ink/gpu-budget.cjs` 量，手机（390×844）峰值 ≤ 120 MB，桌面 ≤ 180 MB；不许涨了不回来（上次闪退就是这个）。
4. **帧：** 每个时刻录一段，长任务（> 50ms）在滚动期间 0 个；M5 扫的时候中端手机目标 ≥ 40 fps。
5. **钉住总长：** Hero 2.6 屏 + Location 1.8 + Masterplan 2 + Facilities 横向（按卡片算，约 2.5）。全站目标约 13 屏（restructure B 定的是约 12，M1 多出 0.6 屏）。
6. **每个时刻都有「减少动态」的版本**，而且那个版本信息不少。
7. **手机先做**：每个时刻先在 390×844 上看对，再看桌面。

## 4. 做的顺序

**第 1 批（wow 最大）：** M5 一天走过 → M6 上墨 → M1 穿过窗子。做完发预览给用户看，**等用户说好再往下**。

**第 2 批：** M3 岛 → 地块（同时完成 restructure B 欠的那一项）→ M4 平面图画出来并缩短。

**第 3 批：** M0 开场、M2、M7、贯穿全站的三项。

每一批：

1. 改代码，`npx eslint src` 干净，`npx vite build` 通过。
2. 用 Playwright 录每个时刻（`page.video`，390×844 和 1440×900 各一段），抽几帧发给用户看。
3. 跑 `gpu-budget.cjs`，写下峰值。
4. 打开「减少动态」（`reducedMotion: 'reduce'`）再截一遍。
5. 提交、推分支、重建相对路径的预览，发到同一个预览 artifact。

## 6. 已经踩过的坑（相关的）

- 墨图每张都占着显存不放 → 手机滚到图就闪退。现在是排队画、画完即放；M5、M6 不能破这个规矩。
- 软件渲染（swiftshader）里量到的帧率比真机慢很多，量帧的时候以「长任务数」和真机为准，不以 swiftshader 的 fps 为准。
- `ScrollTrigger.refresh()` 要在 Facilities 的高度算完之后再调（现在已经这样），新的钉住段加进来后要再检查一遍各段的起止。
